迁移到另一台电脑

1. 旧电脑上先停止服务。
2. 复制项目目录，排除 node_modules/、.next/，但必须带上 data/。注意：data/app.db 里保存着设置页填写的 API Key（明文），这个目录等同于含密钥的文件，别随手分享或提交 Git。.env.local 是可选的，不再需要它提供 Key。
3. 新电脑安装 Node.js 22.16+，执行：

npm install
npm run build
npm run start

原生模块（better-sqlite3）不要跨机器复用，必须在目标机器重新 npm install。

如果不想连带旧 Key：复制 data/ 后，在新机器打开「设置」页，替换或清除 API Key；替换前旧 Key 仍在数据库里。

如果只迁移数据：停止两边服务后，把 app.db、app.db-wal、app.db-shm 一起复制到新机器相同的数据目录。只复制 app.db 可能丢失最近的记录。

放到自己的服务器

这个应用没有登录和多用户隔离，不能直接暴露公网。推荐：

1. 代码放 /opt/ai-learning-coach，数据库持久目录设为 /var/lib/ai-learning-coach。
2. 安装 Node.js 22.16+。模型配置可以在启动后到「设置」页填写（保存在数据库里）；也可以写入生产用 .env.local（权限设为仅服务用户可读）作为兜底：

npm install
npm run build

3. 用 systemd 跑单进程，不要 PM2 cluster 或多副本共用同一个 SQLite 文件：

Environment=NODE_ENV=production
Environment=DATA_DIR=/var/lib/ai-learning-coach
ExecStart=/usr/bin/npm run start -- -H 127.0.0.1 -p 3000

4. 前面放 Nginx/Caddy，必须加 Basic Auth、公司 SSO 或 Cloudflare Access，并开启 HTTPS。AI 生成和流式讲解较慢，建议：

proxy_buffering off;
proxy_read_timeout 300s;

5. 定期备份：

sqlite3 /var/lib/ai-learning-coach/app.db ".backup '/backup/ai-coach-$(date +%F).db'"

没有域名时，更安全的办法是应用只监听 127.0.0.1，通过 SSH 隧道访问：

ssh -L 3000:127.0.0.1:3000 user@your-server

完整的 systemd 和 Nginx 示例已写进 README.md 的“部署到自己的服务器”一节。

claude-pick.bat 的令牌已移到项目目录之外：%USERPROFILE%\.claude-pick.env.bat（POE_AUTH_TOKEN / DEEPSEEK_AUTH_TOKEN）。项目目录本身不再含明文令牌；换电脑时这个文件要单独迁移或重新创建。.env.local 和 data/ 都在 gitignore 里，不会提交；但 data/ 含明文 API Key，拷贝或备份时请按密钥文件保管。
